# Security policy

## Supported version

Security reports should identify the exact application version and source package. The current documentation package describes version **2.0.25 – English Edition**. Older packages may not contain the same checks or safeguards.

## Reporting a vulnerability

Please do not publish exploit details, credentials, private logs, or a proof of concept in a public issue.

If GitHub Private Vulnerability Reporting is enabled for this repository, use the repository's **Security → Report a vulnerability** workflow. Otherwise, contact the repository owner privately through a private channel listed on the owner's GitHub profile. Do not post sensitive details publicly while waiting for a response.

Include, where safe:

- affected application version and source revision;
- Windows edition and build;
- a concise impact description;
- reproduction steps that do not expose personal information;
- relevant redacted logs.

## Safe use

The application requests administrator privileges and can make system-level changes. Run only source or binaries whose origin and integrity you have checked. Review all selected actions before confirming them. See [Safety & Data](docs/SAFETY-AND-DATA.md).
